# Defend It Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use subagent-driven-development with implementation, spec review, then quality review.

**Goal:** A useful, publicly deployable presentation defence coach with verifiable assignment evidence and narration-ready demo.

**Architecture:** Same-origin Node HTTP application with static browser UI and server-side model calls. Model output is schema validated; session and retries are explicit browser state.

**Tech Stack:** Node 22+, built-in HTTP/fetch/test, HTML/CSS/JavaScript ES modules, OpenAI-compatible chat completions.

## Task 1: Working application
- [ ] Build `server.mjs`, `lib/prompts.mjs`, `lib/provider.mjs`, `lib/validation.mjs`, `public/index.html`, `public/app.mjs`, `public/style.css`, `package.json`, `.env.example`, `.gitignore`.
- [ ] Endpoints: `GET /api/status` returns configured boolean and public model label; `GET /api/prompts` exact safe templates; `POST /api/coach` accepts action `claims|question|feedback|retry` and bounded session data. Never accept client-selected model destinations.
- [ ] Claims are source-linked; question is grounded in confirmed claims; feedback cites answer excerpts and supplies gaps/follow-up; retry compares original/revision for same question. Render all untrusted content with textContent.
- [ ] Add `tests/*.test.mjs`: empty/oversized requests, invalid action, malicious content rendered as text, schema rejection, fabricated quotes, provider failure, same-question retry, export content. Run `node --test` expecting zero failures.
- [ ] Add `Dockerfile`, `render.yaml` and secure production configuration instructions. Test `npm start` and missing-model status.
- [ ] Review spec compliance, fix gaps, then review correctness/security/UX and fix findings.

## Task 2: Provider and real verification
- [ ] Resolve authorized hosted model and hosting account without exposing credentials. Run actual claims/question/feedback/retry, preserve non-sensitive sample outputs and timings.
- [ ] Run a small basic-prompt versus engineered-prompt evaluation with identical model/cases; report qualitative limitations without invented improvements.
- [ ] Browser QA desktop and narrow layout, keyboard, loading/errors, retry and download.

## Task 3: Submission pack
- [ ] Write README, rubric evidence matrix, prompt-pattern explanation, deployment guide, actual validation record and live presentation runbook.
- [ ] Prepare 110-second narration with actual product actions, prompt explanations and limitations. Build rehearsal/recording aid from genuine screen capture or truthful replay only after app flow verified.
- [ ] Publish source and deploy when access permits; verify anonymous URL and actual inference. Record remaining human actions (voice-over/live presentation) distinctly from completed work.
